# My Day with Claude Code — March 16, 2026

Professional infrastructure is just another kind of system. March 16 was the day I built mine.

<div style="background: #f0f0f7; border-radius: 6px; padding: 16px 20px; margin-bottom: 24px;" markdown="1">

**Quick read**

A day spent on professional presence and system improvement — LinkedIn aligned, a resume website built and live, and a full review of 132 sessions of AI usage turned into concrete changes. Here's what happened:

- Audited LinkedIn — fixed an end date, added two honours, aligned everything ahead of a specific application
- Built and published a live resume website — custom domain, HTTPS, content polished per feedback
- Generated a resume PDF and got it to the right person via a contact
- Reviewed 132 sessions of AI usage data and implemented every recommendation in one sitting
- Added two new capabilities: a blog publishing pipeline and a document writing pipeline
- Set up a daily operations automation that now runs every morning at 8 AM

A day where the professional and the operational ran in the same direction.

</div>

<p style="margin-bottom: 32px;"></p>

### LinkedIn

It started with LinkedIn — the kind of audit you know you should do more often but don't. I had a specific opportunity I was preparing for, and the profile needed to reflect where things actually stood.

Three changes: a job end date that was wrong by a year, corrected. Two honours that were missing entirely — a government expert committee and a newspaper column — added. The rest was already accurate, which was a small surprise. Once you have a system that tells you what needs updating, the update itself takes twenty minutes.

### A resume that lives on the web

Next: a resume. Not a PDF sitting in a folder — a webpage at its own domain. The thinking: a link is easier to share than a file, and a webpage can be updated without redistributing anything.

The build took one session. A template, adapted. Content edited to match current positioning — the professional summary tightened, interests updated, a section adjusted per feedback from a contact who'd seen an earlier version. Then: custom domain, HTTPS provisioned, verified live.

A PDF version was generated separately for contexts that require it — the kind you attach to a form. Both exist now. The webpage is the living version; the PDF is a snapshot.

The resume went out to a specific opportunity the same day, via a contact who made the introduction.

### The insights session

In the afternoon, something I'd been meaning to do for a while: review the AI usage report.

Claude Code has a built-in insights command. At this point I had 132 sessions logged. The report surfaces patterns — which tools are used most, where things slow down, what's working. I read the whole thing and then did something I should do more often: treated every recommendation as an action item and worked through the list.

What came out of it:

A clearer tool priority order — when to reach for an API, when to use a CLI, when to use browser automation. Written down explicitly so it doesn't have to be re-decided every time.

Two new skills. One for publishing blog posts: a multi-step pipeline that checks for privacy issues, formats correctly, and publishes in the right sequence. One for writing documents: a three-pass quality gate that drafts, reviews against a checklist, and fixes before presenting the result.

And a daily operations automation — a scheduled script that runs every morning at 8 AM: calendar briefing, pending actions, anything that needs attention surfaced before the day starts. It had been on the list for a while. It got built.

### The day that was.

LinkedIn aligned. Resume website live. PDF sent. 132 sessions reviewed, every recommendation implemented. Two new capabilities added. One daily automation live.

What strikes me is that none of this felt like a distraction from the real work — because it *is* the real work. Professional presence, operational systems, daily briefings — these are the infrastructure that everything else runs on. The difference is that building them used to take weeks of scattered effort. This took a day. One focused session, one set of tools, one commit.

You can build this. Not all at once. Not in a day. But piece by piece, the way I've been doing it — one automation, one workflow, one small win at a time. And if you want help getting started, that's exactly what this site is for.
